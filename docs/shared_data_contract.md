# Shared Data Contract

Status: **Checkpoint 0 draft**

This contract is the read-only input for the three specialist agents. No agent may add a shared key, table, endpoint, or data source beyond this contract without an owner checkpoint.

## Lineage Spine

```text
experiment --< run --< checkpoint --< model_version --< eval_run --< eval_output
                |              |
                |              +-- promoted to model_version
       consumes dataset_version
                |
   emits training_metrics + compute_metrics keyed by run_id and node_id

model_version --< deployment --< inference_traffic   optional later phase
eval_failure --> saved as dataset_candidate --> dataset_version closes loop
```

## Shared Conventions

- Timestamps are UTC ISO-8601.
- Event time column is `timestamp`; lifecycle columns may use `created_at`, `started_at`, and `ended_at`.
- All foreign keys are explicit columns with canonical names.
- Dataset versions, model versions, and eval-suite versions are immutable.
- Analytical time-series tables use long format: `entity_id`, `timestamp`, `step`, `metric_name`, `metric_value`.
- Analytical data lives in Parquet + DuckDB.
- App metadata lives in Postgres.
- Raw records and artifacts live in local object-store-style folders.
- Data source labels are required for provenance:
  - `PUBLIC_REAL`: real public large-size downloaded data
  - `GENERATED_REAL`: real data generated by local pipelines, quality jobs, model runs, or eval runs
  - `SYNTHETIC_REALISTIC`: constrained synthetic data used only when public/generated real data is unavailable, too expensive, or too slow

## Contract Amendments

Any new shared key, table, enum value, or cross-agent edge must be proposed in a checkpoint with:

1. The exact field or table name.
2. The owner agent and consumers.
3. The lineage question it enables.
4. The storage layer where it belongs.
